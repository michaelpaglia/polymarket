# Contributing Guidelines

## Branch Strategy

- **Main branch is protected** - Do not commit directly to `main`/`master`
- **Feature branches required** - All new features must be developed on separate branches
- **Branch naming**: `feature/<name>`, `fix/<name>`, `refactor/<name>`

```bash
# Create a feature branch
git checkout -b feature/new-strategy

# Work on your changes...

# Push the branch
git push -u origin feature/new-strategy

# Create a PR to merge into main
```

## Commit Guidelines

### Do
- Write clear, concise commit messages
- Use conventional commit prefixes: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`
- Keep commits atomic (one logical change per commit)
- Reference issue numbers when applicable

### Do Not
- Do not add AI/LLM attribution in commits (no "Generated by...", "Co-authored-by: Claude", etc.)
- Do not commit directly to main for new features
- Do not commit sensitive data (API keys, private keys, credentials)

### Commit Message Format

```
<type>: <short description>

<optional longer description>

<optional footer>
```

Examples:
```
feat: add WebSocket reconnection logic
fix: handle empty orderbook response
docs: update API endpoint documentation
refactor: extract market matching into separate module
```

## Code Standards

### Python
- Type hints required for all functions
- Use `pyright` for type checking
- Use `ruff` for linting
- Follow existing code patterns

### Rust
- Run `cargo clippy` before committing
- Run `cargo fmt` for formatting
- Add tests for new functionality

## Pull Request Process

1. Create a feature branch from `main`
2. Make your changes with clear commits
3. Ensure all tests pass
4. Update documentation if needed
5. Create a PR with a clear description
6. Wait for review before merging

## Development Setup

```bash
# Python
pip install -e ".[dev]"
pyright src/
ruff check src/

# Rust
cd rust-hft
cargo test
cargo clippy
```
